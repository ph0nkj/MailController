## Что проверено в интерфейсе

### Навигация и заголовки

- «Campaigns» больше не дублируется в топбаре: заголовок страницы один, в топбаре
  только «Local admin» и «Sign out».
- Все пять пунктов навигации доступны, активный пункт подсвечивается.
- Логотип загружается на странице входа и в сайдбаре (реальный PNG 256×256,
  `naturalWidth=256`), favicon отдаётся приложением.

### Размер страниц и переполнение

Найдены и исправлены две причины проблем с раскладкой:

- корневой `#app` постоянно имел класс `boot` с `display: grid`, из-за чего
  ширина приложения зависела от содержимого страницы. Класс `boot` теперь
  относится только к загрузочному элементу внутри `#app`;
- у анимированного `.view` оставался `transform`, поэтому `position: fixed`
  у модальных окон считался относительно страницы, а не viewport. Переход
  страницы теперь использует только плавное изменение прозрачности, а модальное
  окно и затемнение корректно покрывают весь экран.

Результат на десктопе 1440×900:

| Страница | Ширина контента |
| --- | --- |
| Dashboard | 1181 px |
| Campaigns | 1181 px |
| Settings | 1181 px |

Ширина одинаковая на всех страницах. Проверки на 390×844:

- горизонтального переполнения страницы нет ни на Dashboard, Campaigns,
  Settings, ни в модальном окне;
- таблица кампаний прокручивается внутри своего контейнера, а не растягивает
  страницу;
- длинное имя кампании (112 символов) и длинная тема переносятся/обрезаются
  внутри ячейки;
- все поля и кнопки остаются внутри карточек;
- мобильная шапка показывает логотип, полное имя и пять иконок навигации.

### AI-подключение

Проверен полный пользовательский сценарий через реальный UI:

1. На чистой базе AI-карточка показывает **Not configured**, поле только для
   API-ключа, provider/model скрыты в свёрнутом **Advanced settings**.
2. Неверный ключ → **Not connected**, понятная ошибка, поле ключа очищается.
3. Валидный OpenAI-тестовый ключ → **Connected · gpt-4o-mini**, провайдер
   определён автоматически.
4. Ключ Anthropic (`sk-ant-…`) → **Connected · claude-sonnet-4-5**, провайдер
   определён автоматически.
5. После перезагрузки Settings статус **Connected** появляется автоматически
   (без нажатия кнопки), Advanced settings остаётся свёрнутым.
6. `/api/v1/llm/status` не возвращает ключ; ключа нет в DOM, localStorage и
   sessionStorage.
7. В SQLite настройки лежат только в `llm.config_enc`; тестовый ключ в открытом
   виде не найден. Логи приложения тестовый ключ не содержат.

### Переходы и адаптивность

- Переход между страницами использует анимацию `.view` (`view-in`, 0.26 s).
- Модальные окна и тосты анимированы (`modal-in`, `toast-in`).
- При `prefers-reduced-motion: reduce` длительность анимаций падает до
  `0.00001 s` (проверено через эмуляцию media feature).
- Модальное окно кампании на мобильном полностью помещается в viewport:
  фон перекрывает все 390×844, шапка и кнопка закрытия видны.
- На мобильном ширина ровно 390 px, без горизонтального скролла страницы.
- Кнопки, поля и карточки не выходят за границы экрана.

## Google OAuth

`test/check-google-creds.py` отправляет заведомо неверный authorization code на
`https://oauth2.googleapis.com/token`:

```
google_token_http=400
google_oauth_error=invalid_grant
google_client_credentials=accepted
```

Это подтверждает, что client id/secret (и redirect URI из `.env`) приняты
Google. Полный вход в Gmail-аккаунт не выполнялся: для него нужен браузерный
consent и реальный ящик, поэтому чтение писем, очистка и отправка кампаний в
этом прогоне не проверялись.

## Ограничения

- Реальные OpenAI/Anthropic API не вызывались — ключей нет. Проверены протокол,
  автоопределение провайдера, состояния UI и обработка ошибок через mock.
- Gmail OAuth-подключение и реальная отправка писем не тестировались.
- Кампания создана через API только для проверки вёрстки; рассылка не
  запускалась.
- Мобильная проверка выполнена через эмуляцию Chrome DevTools (390×844), не на
  физическом устройстве.

## Артефакты тестового прогона

- `test/run-ui.sh` — поднимает mock LLM, приложение и headless Chrome, запускает
  браузерные проверки.
- `test/e2e.mjs` — 77 проверок UI через Chrome DevTools Protocol; без npm-зависимостей.
- `test/mock-llm.py` — локальный OpenAI/Anthropic-совместимый mock.
- `test/check-google-creds.py` — проверка Google OAuth-креденшелов без вывода секретов.
- `test/data/ui-results.json` — машинный результат UI-прогона.
- `test/screenshots/01-login-desktop.png` … `14-settings-ai-mobile.png` — скриншоты
  десктопа и мобильной версии, включая состояния AI **Not connected** и **Connected**.
  В скриншотах используется демонстрационный Google OAuth client; реальные
  идентификаторы и секреты не публикуются.
